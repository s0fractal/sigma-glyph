# Σ-GLYPH Specification Conformance Suite

Machine-readable test vectors for all three Books and the constitution:
`vectors.json` (Book I, TRUTH — 49 eval/object/deserialize vectors),
`wave_vectors.json` (Book II, NAVIGATION — interfere/term/iterate/coordinate
kinds), `federation_vectors.json` (Book III, FEDERATION —
validation/selection/wave_fed/view kinds), and `governance_vectors.json`
(GOV-anchors.md — 20 full-store adoption scenarios incl. the gate's attack
fixtures: minted-pair hijack, closure orphans, jurisdiction replay, rival
freeze, both P1-R directions). Purpose: an implementation in any language can
claim conformance per document by passing its suite — without reading the
Python reference implementations.

## Files

| File | Role |
|------|------|
| `vectors.json` | The vectors. **Generated, never hand-edited.** |
| `generate.py` | Regenerates `vectors.json` from the oracle (`impl/sigma_glyph.py`). |
| `wave_vectors.json` / `federation_vectors.json` | Book II / Book III suites. Generated by `impl/sigma_wave.py gen` and `impl/sigma_federation.py gen`. |
| `governance_vectors.json` | GOV suite: each vector embeds a complete deterministic `.warrants` store (fixed seeds, RFC 8032, fixed ts) + trust config + expected verdict. Generated by `tools/anchor_governance.py gen`; replay with `tools/anchor_governance.py replay`. |
| `run_reference.py` | Replays `vectors.json` against the Book I oracle; also executable documentation of runner semantics. |
| `test_properties.py` | Seeded property tests (determinism, ATP exactness, canonicity round-trip, C1 purity, P7 memory bound). Stdlib-only. |

## vectors.json format (`format_version: 3`)

The **normative** shape is
[`spec/schemas/book1-conformance.schema.json`](../../spec/schemas/book1-conformance.schema.json),
anchored in `spec/ANCHORS.txt` beside the suite. It is closed: an unknown field
makes a record invalid. What follows is a reading aid, not the definition —
`python3 tools/suite_schema.py` decides.

Top level:

```jsonc
{
  "format": "sigma-glyph-conformance",
  "format_version": 3,
  "spec_version": "0.6.0",        // Book I DOCUMENT version the vectors conform to
  "suite_version": "0.6.0",       // conformance-suite PACKAGE version
  "book1_anchor": "…",            // Specification Anchor of that Book I
  "oracle": "impl/sigma_glyph.py",
  "objects": { "<node-hash-hex>": "<canonical-bytes-hex>", … },
  "vectors": [ … ]                 // 49 in this release; eval vectors MAY carry
                                   // store_subset (format v2) for isolation runs,
                                   // and carry expected.exit from format v3
}
```

`spec_version` and `suite_version` can differ: the suite may grow vectors in a
release that does not touch Book I text. A conformance claim cites both plus
`book1_anchor` — the anchor is the unambiguous one.

**Setup:** insert every entry of `objects` into your CAS. Keys are the SHA-256
NodeHash of the bytes — verify this while loading. One object is deliberately
*malformed* (Era-1 `0x03` opcode): a CAS stores bytes, not judgments; its
validity is decided at `resolve()` time (Book I §3.5b, §4.1).

**Vector kinds:**

- `kind: "object"` — serialization/hash conformance.
  Hashing `bytes` MUST yield `expected.hash`.

- `kind: "deserialize"` — negative validation.
  `bytes` MUST fail §4.1 validation (⇒ materialize the Canonical Invalid
  Object, §4.2). `expected.valid` is always `false`.

- `kind: "eval"` — the core contract.
  `eval(term, atp, env)` MUST produce a `Receipt` whose `exit` is
  `expected.exit`, whose result NodeHash is `expected.result_hash`, and which
  spends exactly `expected.atp_spent` ATP under **tree semantics** (Book I §3.4,
  TV-6).

  **All four are normative, and `exit` and `outcome` are different things.**
  `expected.exit` is `Receipt.exit`, a closed enum of three:
  `normal_form` | `atp_exhausted` | `unresolved_reference`. `expected.outcome`
  is a suite-level *classification* of the result and carries one more value,
  `invalid_object`, which names a `normal_form` exit whose result is the
  Canonical Invalid Object (§4.2) — **not a fourth exit**.

  This README said `outcome` was informative until 2026-08-30, while the
  candidate specification declared it normative and the runner checked neither
  it nor the exit. `run_reference.py` now reads a `Receipt` and checks the four
  as four separate claims; `tests/conformance_runner_selftest.py` mutates each
  in turn and requires it to fail on its own.

Dissonance outcomes need no special casing: `DISSONANCE(ATP Exhausted)` and
`DISSONANCE(Unresolved Reference)` are canonical nodes with fixed hashes, so
comparing `result_hash` covers them uniformly.

## What these vectors are evidence of (read before citing them)

A vector file generated by an oracle and replayed against the same oracle
proves only that the oracle has not *changed*. It cannot show the oracle was
right in the first place. Until v0.6.7 that was the whole story for Books I and
II: `generate.py` wrote `sg.eval_hash(...)`'s own answer into `expected`, and
`run_reference.py` handed it straight back. Ground truth reduced to five
genesis hashes.

Both generators now carry **hand-written, spec-cited expectations** and
**refuse to write their vector file** when the oracle disagrees with one — the
discipline `tools/anchor_governance.py` (`cmd_gen`) has had since v0.6.x. Those
vectors constrain the oracle instead of mirroring it. The rest do not, and this
table says which is which. `tests/spec_expectation_guard.py` is the negative
control: it breaks one normative behaviour at a time in a scratch copy of the
oracle and requires the refusal to fire and name the right vector.

| Suite | Spec-derived (constraining) | Oracle-generated (regression-only) |
|---|---|---|
| `vectors.json` (Book I) | **47 of 49** — 31 quoted verbatim from `spec/book-1-truth.md`, 16 hand-computed from its rules | 2 — `EV-REF-COMBINATOR-FIRES`, `EV-K-DEAD-NESTED-MISSING` |
| `wave_vectors.json` (Book II) | **16 of 17** — 9 quoted from `spec/book-2-navigation.md`, 7 hand-computed; plus the §4 LUT arbiter/anchors/controls and the §6.1 Trinity pins | 1 — `WV-ITER-DECAY` |
| `federation_vectors.json` (Book III) | 0 declared | all 21 — no declarations written yet; Book III's normative text is procedural rather than numeric, but this is untried, not impossible |
| `governance_vectors.json` (GOV) | all 20 — hand-declared verdict + note per scenario | 0 |

*Quoted* means the expected value is printed in the spec: every Book I §7 test
vector with its exact ATP count (TV-4's 4, TV-5's 12, TV-6's 21, TV-8's 4,
TV-9's 6, TV-10's 20, TV-11's 7 and 20, TV-12's 3 and 0), the §5.1 genesis
NodeHashes, the §5.2 FALSE hash, the §4.2 Canonical Invalid Object, the §5.3
reason hashes, and every §7 term hash. *Hand-computed* means derived here from
a stated rule — the §3.4 cost table, the §3.5 resolution contract, the §1.1/§2
byte layout — with the arithmetic written out in the declaration's `cite`.

Honest limits of this:

- The declarations were written by reading the spec, by one author, in one
  pass. They are as fallible as any hand-derivation; what they are *not* is a
  copy of the oracle's output.
- The §1.1/§2 serializer used to derive node hashes is a second, four-line
  implementation living in `generate.py`, not the oracle's. It is itself checked
  against every node hash the spec quotes (`SPEC_SELFCHECK`) — but it and the
  oracle could still share a misreading of the same English sentence.
- Book III and the two remaining Book I vectors are unconstrained. Nobody
  should describe this suite as "independent of the implementation"; the
  accurate statement is "47/49 Book I and 16/17 Book II expected values are
  pinned to the specification text, and generation fails closed if the
  implementation contradicts them."
- Passing the suite still says nothing about resource behaviour: Book I §3.6
  local faults are deliberately outside the canonical outcomes and therefore
  outside every vector here.

## Claiming conformance

1. Load `objects`, verifying CAS keys.
2. Pass all `vectors` (49 in this release).
3. State the `spec_version`, `suite_version` and `book1_anchor` you tested against.

Passing this suite demonstrates conformance on the covered surface; it does
not replace reading Book I. The suite grows — new findings become new vectors
(review protocol: `reviews/README.md`).

## Regenerating

```
python3 tests/spec_conformance/generate.py     # rewrites vectors.json from the oracle
python3 tests/spec_conformance/run_reference.py
python3 tests/spec_conformance/test_properties.py
```

Regeneration is deterministic: same oracle → byte-identical JSON. CI enforces
that a stale `vectors.json` (one that no longer matches the oracle) fails.
